# 文档转 AI 文本

把 **PDF**、**PPT** 和 **HTML / Outlook 邮件** 转成带位置与格式信息的结构化文本，让 AI 能照着还原成 PPT；
再把改过的文本**直接转回真 .pptx**。两个方向都在同一个工具里。

```
PDF / PPTX / 邮件 ──①──▶ 结构化文本 ──（你让 AI 改内容）──▶ 结构化文本 ──②──▶ .pptx
```

②这一步**不经过 AI 写代码**：坐标写多少就是多少，同一份文本每次生成完全一致。

> 目录名还叫 `PDF转AI文本`（历史原因，没改以免打断你现有的引用），
> 但工具本身已经是 PDF + PPT 二合一，产物叫 `文档转AI文本.*`。

---

## 三种用法

| | `文档转AI文本.exe` | `文档转AI文本.html` | `pdf2ai.py` |
|---|---|---|---|
| 定位 | **本机日常用这个** | 传到别的机器用这个 | 命令行 / 批量 |
| 安装 | 双击即可 | 不需要，记事本粘贴即可 | `pip install pymupdf` |
| PDF | ✓ 两套引擎，一键切换 | ✓ 自写引擎 | ✓ PyMuPDF |
| PPT | ✓ | ✓ | ✗ |
| 导出图片 | ✓ | ✗ | ✓ `--export-images` |
| 体积 | 34 MB | 257 KB（纯文本） | 62 KB |

界面上两个页签：

- **① 文件 → AI 文本**：拖 `.pdf` `.pptx` `.potx` `.mht` `.mhtml` `.htm` `.html`，**可以混着拖**。
  旧版 `.ppt` 需先另存为 `.pptx`。Outlook 邮件建议「另存为 → 单个文件网页(.mht)」，
  图片会一起打包；如果存成 `.htm`，请把同名 `_files` 文件夹里的图片一并拖进来。
- **② AI 文本 → PPT**：粘结构化文本，出 `.pptx`。①那边还有个「直接转成 .pptx」按钮，一键走完往返。

②是**纯 JS 直接写 .pptx**，不依赖 Python，所以单独那份 HTML 也能用这个功能。

**exe 首次运行 Windows 可能弹 SmartScreen 警告**（没有代码签名证书）：
点「更多信息」→「仍要运行」。之后不再提示。

## HTML / Outlook 邮件：为什么它是第三条路

HTML **没有坐标**。PDF 里字有 (x,y)，PPTX 里形状有 xfrm，而 HTML 是流式布局——
位置是浏览器排出来的，文件里根本没有。

但这个工具本身就跑在浏览器里，**浏览器就是排版引擎**。所以做法是：
把清洗过的 HTML 塞进隔离的离屏 iframe 真排一遍，再用 `getBoundingClientRect` +
`getComputedStyle` 把真实坐标与真实样式量出来。于是 HTML 与 PDF/PPTX 共用同一套坐标契约，
②那条线一行都不用改。

代价要讲清楚：**坐标依赖渲染宽度和本机字体**。换宽度、或本机缺字体导致换行不同，
坐标就会变。输出文首会写明用的是哪个宽度，这一条也写进了给 AI 的说明。

### ⛔ 追踪像素：本工具主动掐断

邮件里的远程图片（`<img src="http://...">`）**就是追踪像素**——一加载，
发件人立刻知道收件人在什么时间读了这封信，很多还带着绑定你邮箱的 ID。
本工具承诺不联网，所以渲染前会把所有 http(s) 资源改写掉，只放行 `.mht` 里的内嵌图（`cid:`）
和 `data:`。三层防御：预清洗改写 URL + iframe `sandbox`（禁脚本）+ 文档内 CSP。

被掐断的图**仍然给出准确的位置和尺寸**，输出里会明确要求 AI 按这个尺寸留白。
输出文本里只写文件名，**query string 里的追踪 ID 会被剥掉**，不会跟着粘给 AI。

这条不是纸面承诺：浏览器自检里有一条断言用 `PerformanceObserver` 监听整个渲染过程，
要求外部请求数为 **0**。

### Outlook 的私货

`<!--[if mso]>` 条件注释、`<o:p>`、VML `<v:shape>`、嵌套版面表格——都得处理：

- **mso-only 内容要删**（不删会被当成正文显示出来），
  但 **downlevel-revealed（`<!--[if !mso]><!-->`）里的内容必须保留**——这条最容易搞反
- 一封邮件里十几个 `<table>` 大多是**版面容器**不是数据表。全当数据表会输出一堆假表格
  并把正文吞进去（PDF 那边踩过同款）。判据用结构信号：有 `<th>`、单元格有边框、
  内容够短、内部不再嵌表格

## PDF 与 PPT 是两条完全不同的路

这一点直接决定了输出里哪些数字能信：

| | PDF | PPTX |
|---|---|---|
| 文件里存的是 | **绘图指令**：把某个字画在某坐标、从这点画条线到那点 | **语义对象**：这是个圆角矩形，填充 #1F6F8B，里面有个段落 |
| 段落/表格/文本框 | **不存在**，得从几何关系反推 | 直接就有 |
| 输出可信度 | 坐标颜色字号是[实测]；段落、表格、分栏、图表是[推断]带置信度 | **几乎全是实测值** |

所以输出里做了三级标注：

- **没有标记的数值** —— 文件里的原始值，精确，AI 应当照抄
- **`[推断 置信度x.xx]`** —— 从几何关系重建的，置信度低时 AI 可按常识调整
- **`无法确定` / `�`** —— 确实解不出来。**绝不拿猜测顶替**——一个自信的错误比一句「不知道」有害得多

文末还有一份**给 AI 的自检清单**，逼它交付时说明补了什么、改了什么。

## PPT 侧：修掉了「图层信息没转化」

原来的 `PPT转AI文本` 工具**从未读取过 slideLayout / slideMaster**
（全文 grep：`slideLayout` 出现 0 次）。造成四个症状：

1. 版式/母版上的 logo、色条、装饰线、页脚**完全不可见** → AI 还原出来的页面是空的
2. **占位符没有位置** —— PowerPoint 对继承版式位置的占位符不写 `<a:xfrm>`，
   原代码见到没有就 `return null`
3. 背景几乎总是缺失（只读幻灯片自己的 `<p:bg>`）
4. 占位符文字**没有字号**（字号来自版式 `lstStyle` / 母版 `txStyles`）

现在全部解析出来，并且：

- **模板元素只列一次**。开头有个「版式库」，每个版式的装饰元素描述一遍，
  每页只写「使用版式 X」。12 页的 PPT 不会多出 12 份一模一样的 logo，
  AI 也知道该建母版而不是每页重画。
- **继承来的值会标注来源**：`位置: x=1.27 y=0.76 … ← 继承自母版`，
  并写明「幻灯片上没写死位置，PowerPoint 用的就是这个值」，AI 才敢用。
- 顺带修：`hidden="1"` 的形状**跳过并计数**（原来照样输出，AI 会把看不见的东西画出来）；
  图片 `<a:srcRect>` **裁剪百分比**会提取；主题 `fontScheme` 会解开 `+mj-lt` / `+mn-ea` 引用。

原来那两个工具（`PPT转AI文本`、旧的 `PDF转AI文本`）保留不动，但已被本工具取代。

## ② 文本 → PPT 能还原什么

**能**：页面尺寸与背景、文本框（逐段逐 run 的字号/粗斜体/字体/颜色/对齐）、
矩形圆角矩形椭圆三角形等预设形状（填充/渐变/边框/虚线/旋转/翻转）、线条、
表格（行列、列宽行高、逐格文字）、组合内部坐标系的换算、
以及**把「版式库」还原成真正的 slideLayout**（模板元素定义一次，不在每页重复）。

**不能**：图片（文本里没有像素，画成带文件名的虚线占位框，位置给你留着）；
真图表对象（「疑似图表」按文本给的柱子几何原样摆成矩形，形状一致但不可编辑）；
阴影发光等效果。

> 让 AI 改内容时，让它**只改引号里的文字**，别动「位置:」那些行。

## 能提取什么

### PDF

**实测（精确）**：页面尺寸与旋转、每段文字的内容与坐标、字体名/字号/粗斜体/颜色/透明度、
矢量图形的路径与填充边框虚线渐变、图片位置与压缩格式、绘制顺序（z 轴）、文档大纲、
生成工具元数据、**加密 PDF 自动解密**（空口令的 RC4 / AES-128 / AES-256 全支持）。

**推断（带置信度）**：行合并成段落、段落归成文本块、多栏阅读顺序、页眉页脚识别、
表格行列还原、柱状图/饼图/折线图的几何还原、背景色块识别。

**明确跳过并告知**：隐藏图层（OCG 关闭）、不可见文字（渲染模式 3）、
面积极小的碎路径（**会报出跳过了多少个**）。

### PPT

形状类型与几何、填充（纯色/渐变/图案/图片）、边框、阴影发光倒影、
逐 run 的字号字体粗斜体颜色字距上下标、段落对齐行距项目符号缩进、
文本框锚点与内边距、表格逐格格式与合并、图表类型与全部数据系列、
组合层级与内部坐标系、z 轴顺序、**版式与母版继承链**。

## 不能提取什么

- **图片像素** —— HTML 版只给位置和文件名；要图用 exe 的「高保真重解析」或 `--export-images`
- **扫描件里的文字** —— 没有文字层，需要 OCR，本工具不做
- **SmartArt 内部布局** —— 降级成组合形状
- **动画与切换效果**
- **字体文件本身** —— 只给字体名，还原时目标机器得有同名字体

## 开发

```bash
python build.py           # src/ 拼成单文件 HTML
node test/run.js          # 274 项测试
python build_exe.py --deploy   # 打包 exe + 双重自检 + 放桌面
```

测试分三层：

1. **单元层**——自写的 inflate / MD5 / SHA-2 / RC4 / AES 全部拿 Node 内置 `zlib`、`crypto`
   当标准答案对照；自写 XML 解析器验命名空间、实体、CDATA、注释、引号容错。
   这几块错了不抛异常，只会静默产出错数据，没有对照等于没测。
2. **精度层**——手写的 PDF、python-pptx 生成的 PPT，每个数值都是已知的，逐项断言。
   PPT 夹具（`test/fixtures/inherit.pptx`）专门埋了母版色条、版式角标、
   无 xfrm 的占位符、隐藏形状，就是为了钉死继承链。
3. **集成层**——真实 PDF / PPT，断言无 `undefined`、无 `NaN`。
4. **★ 往返层**——PPT → 文本 → PPT → 文本，比对两次文本。
   两个方向同时错、且错得一致的概率极低，所以这是最强的单条验证。
   生成的文件还额外过了两道**独立**校验：python-pptx 能打开并读出正确结构，
   以及**真实 PowerPoint 用 COM 打开、按名字认出版式、渲染成 PNG 肉眼核对**
   （母版色条、版式角标、继承坐标、字号全部对得上）。

**浏览器端自检**（渲染量测那条路 Node 测不了，没有 DOM）：
`python -m http.server` 起在工程根目录，然后打开
`文档转AI文本.html?selftest=1`，页面会直接列出 11 项结果、标题显示通过与否。
最关键的一条是「渲染全程零外部请求」——用 `PerformanceObserver` 监听，
这是追踪像素有没有漏放行的唯一硬验证。

打包后的两道自检缺一不可：`--selfcheck`（含真实中文样本走完整链路）+
`--uicheck`（**真把窗口开出来再关掉**）。解析自检过 ≠ 界面能开。

## 技术说明

- **自己实现了同步 inflate**（~150 行），PDF 和 PPTX 解压共用。
  用浏览器原生 `DecompressionStream` 会让整条调用链被迫异步，而解压点埋得极深。
  代价换来逻辑同步好读，以及不再依赖 `DecompressionStream`。
- **自己实现了 XML 解析器**（~120 行），不用 `DOMParser`。
  否则 Node 测试台跑不了 PPTX 这条链路，等于这部分永远没有自动化回归。
- **写 .pptx 不需要压缩器**：ZIP 允许「存储」模式（method 0），PowerPoint 完全接受
  不压缩的 .pptx。于是只要 CRC32 + ZIP 打包（约 30 行）就够，不必实现 deflate。
  这保住了「单文件 HTML、零安装」——走 python-pptx 的话这功能就只有 exe 版能用。
- **自己实现了 MD5 / SHA-2 / RC4 / AES**，为的是支持加密 PDF（研报白皮书里很常见）。
  Web Crypto 做不了 AES-256 R6 口令散列需要的「无填充 CBC 加密」。
- **xref 坏了会自动全文件扫描重建**。
- PPTX 引擎整个包在 IIFE 里：拼进单文件后和 PDF 引擎同处一个作用域，
  `UNIT`/`COMPACT`/`color`/`fill` 这些名字两边都有，不隔离会直接撞成语法错误。
- 文件全程只在本机内存里处理，**不上传任何地方**，也不联网。

> ⚠️ 但你把生成的文本粘给 AI 时，文本会离开这台机器。工具本身不联网，之后怎么用是你的判断。

## 已知的坑（修过了，留档）

- **★ PPT 的版式/母版整层缺失**（上面详述）。元教训：原代码其实输出了
  `占位符: 类型=title（格式可能继承自版式/母版）` 这句提示——作者知道有继承这回事，
  但只留了句话给 AI。**提示不是数据**，AI 拿不到值只能瞎猜。
- **★ 「找到了匹配」≠「拿到了值」**。修继承时第一版只找第一个匹配的占位符就返回，
  但默认模板里版式的占位符自己也不写 `xfrm`（再往上继承母版），
  于是报「无法确定」——而那个值在母版上明明有。
  OOXML 的真实语义是**每个属性各自沿链独立解析**。
- **字间距被当成词间距**。Skia/Chromium 用 TJ 调整实现 CSS letter-spacing，
  固定阈值 0.2em 会把 `LATAM` 拆成 `L A T A M`。修法不是调阈值——固定阈值必然两头不讨好。
  判据换成**「这个间隙相对本行其它间隙是不是异常大」**，按行自适应。
- **整页装饰边框被判成「N 行 × 1 列的表格」**，吞掉整页正文（4459 字 → 673 字）。
  加硬约束：行、列都必须 ≥ 2。
- **表格单元格按整行分配**：一行横跨三列时，行的中心点永远落在中间列。改成按文字片段分配。
- **整张表格的框线画在一个路径里时整个漏检**。只看路径外接框会一条线都抽不出来，
  改成逐子路径判断。**这条是拿 Python 版交叉验证时发现的**——
  两个独立实现跑同一份输入，分歧点直接指向 bug。
- **StemV 不能用来判粗体**。实测 Skia 导出的 PDF：真粗体 StemV=84，常规体 StemV=488，
  **方向是反的**。这不是调参能救的，是判据选错了维度。只认结构信号（`-Bold` 后缀等）。
- **`attr()` 的返回值直接拼进输出串**：`<c:legendPos>` 允许省略 `val`，
  于是真实 PPT 上打出了「图例: undefined」。所有会被拼进串的属性读取都要给默认值。
- **空的 Flate 流被当成解压失败**，掉进容错分支后吐出 924 字节垃圾。
  「成功但结果为空」和「失败」必须分开判。
- **状态文件写在 `webview.start()` 之后**——那个调用阻塞到关窗，
  等于在最需要排障的场景（「双击了没反应」）下什么都不写。诊断必须在开窗前落盘。

- **「版式库」不能跳过，也不能塞进每一页**。反向管线第一版把版式库整段跳过了
  （理由是"那是模板描述不是页面内容"），结果生成的 PPT 少了 logo 和色条。
  但塞进每一页又正是版式库要避免的重复。正解是**真的生成 slideLayout**：
  一个母版 + N 个版式，幻灯片引用对应版式，PowerPoint 自会渲染到每一页 ——
  视觉一致、定义一次，与原文件结构同构。这条也是我在 preamble 里叮嘱 AI 做的事，
  自己的生成器不做就说不过去。

- **★ 源码里绝不能写字面量控制字符**。8-topptx.js 里「剔除 XML 非法字符」的正则
  写成了字面量 `[ -…]`（真的控制字节）。**Node 直接读源文件，字节原样进正则，
  范围有序，274 项测试全绿；但浏览器要先过 HTML 解析器，而 HTML 规范强制把 U+0000
  换成 U+FFFD** ⇒ 字符类范围逆序 ⇒ SyntaxError ⇒ 整个脚本一行都不执行。
  两条路径的解码管线不同，测试台全绿而真实环境全挂。已加成 `build.py` 的构建期硬检查
  （塞一个坏文件进去验证过确实会拦并退出码 1）。
- **等布局稳定不能用 `requestAnimationFrame`**。rAF 在页面不可见时根本不触发——
  浏览器后台标签、以及 exe 窗口被最小化时都是这个状态，一旦依赖它，HTML 转换会直接
  卡死到超时。改用 `setTimeout`，它不看可见性。
  （首版就是这么超时的，而且只有在真浏览器面板里跑才暴露。）
